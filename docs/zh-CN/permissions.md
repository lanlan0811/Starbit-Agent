# 权限与安全模型

Starbit 把所有内置工具、MCP 工具和技能脚本统一送入权限引擎。权限模式决定默认行为，规则决定特定例外，危险命令规则提供不可轻易绕过的上限。模型本身不能批准操作。

## 三级权限矩阵

| 操作 | 计划 `plan` | 自动编辑 `acceptEdits` | 完全访问 `fullAccess` |
|---|---|---|---|
| 读取、列目录、搜索 | 自动允许 | 自动允许 | 自动允许 |
| 创建目录 | 自动允许 | 自动允许 | 自动允许 |
| 匹配计划规则的 Markdown 文档 | 创建和修改均允许 | 自动允许 | 自动允许 |
| 其他文件写入/编辑 | 拒绝 | 自动允许 | 自动允许 |
| 普通 Shell | 拒绝 | 询问 | 自动允许 |
| 风险级别 1 的脚本/外部工具 | 拒绝 | 询问 | 自动允许 |
| 高风险工具或警告级命令 | 拒绝或询问，取更严格结果 | 询问 | 询问 |
| 内置阻断级危险命令 | 拒绝 | 拒绝 | 拒绝 |

“完全访问”并不会关闭危险命令检查。内置 `block` 规则，例如磁盘格式化、磁盘清理、整盘清空或特定提权操作，会直接拒绝；`warn` 规则会要求确认。规则库会继续迭代，因此具体判定以确认弹窗和审计记录为准。

## 计划文档

默认计划文档判定为：工作区内、扩展名为 `.md`，且文件名包含“计划”或 `plan`（不区分大小写）。计划模式允许反复创建和修改同一份计划，而不只是第一次创建。

仅把文件命名为计划文档不应被用来隐藏可执行代码或大规模非计划改动。若目标文件不匹配规则，切换模式前先核对路径和用途。

## 工作区边界

相对路径从会话工作区解析；绝对路径经过规范化后必须落在工作区或用户显式授权的根目录。`..`、符号路径表示或大小写差异不能作为越界手段。默认不要把用户主目录、磁盘根目录或共享敏感目录选作工作区。

Shell 命令的当前目录是工作区，但 Shell 本身可能通过绝对路径、网络或子进程触达更大范围。因此 Shell 还受模式、危险规则和确认流程约束；工作区文件边界不等于操作系统沙箱。

## 权限规则

规则由三部分组成：语义标签、匹配模式和动作。示例：

```text
Bash(pnpm test *)       allow
Write(./docs/**)        allow
MCP:filesystem:read_*   allow
```

实际存储结构使用 `semanticLabel` 与独立 `pattern`，通配符 `*` 和 `?` 可参与匹配。尽量使用最窄的命令或路径，不要批准 `Bash(*)`、`Write(*)` 或整个主目录。

规则动作有 `allow`、`deny`、`ask`；作用域有：

- 本次：只决定当前弹窗，不保存复用规则。
- 本会话：同一语义标签和目标在当前 Agent Loop 生命周期内复用。
- 永久：本地持久化允许规则，后续会话可命中。

当前确认流程只会为“允许”创建会话级或永久规则；拒绝会反馈给 agent，但不会静默转成永久拒绝规则。已保存规则应定期复核和删除。

## 确认弹窗

确认前至少检查：

1. 工具名和来源是否符合任务，例如内置、`mcp:<server>` 或 `skill:<name>`。
2. 展示的完整命令是否包含管道、重定向、命令替换、下载后执行或隐藏参数。
3. 目标路径是否精确，是否会覆盖、递归修改或离开工作区。
4. 影响描述与当前请求是否一致。
5. “本会话”或“永久”授权是否真的需要；不确定时选择本次。

拒绝后最好填写简短原因，例如“只能读取该目录”或“不要访问网络”。原因会返回给 agent，帮助其选择更安全的替代方案。

## 危险命令规则

内置规则覆盖 Windows 和常见类 Unix Shell 中的递归强制删除、磁盘格式化、下载管道执行、注册表修改、提权及磁盘清理等模式。匹配针对完整命令且不区分大小写。

`resources/dangerous-rules.yaml` 用于项目维护的规则清单。无效正则不应导致应用崩溃；自定义规则必须经过测试。规则匹配是防御层，不是完整 Shell 解析器，复杂别名、编码载荷或解释器嵌套仍需人工识别。

## MCP 与 Skills

MCP 工具名规范为 `mcp__<server>__<tool>`。服务器提供的 `readOnlyHint` 与 `destructiveHint` 参与初始风险分类，但远程声明本身不受信任；未知或有副作用的工具按更严格方式处理。MCP 返回值会标记为不可信数据。

技能正文是操作指南，不会获得额外权限。`scripts/` 下脚本作为独立工具注册，执行前经过同一权限引擎；脚本仍运行在主机用户权限下，应先审查来源与内容。

## 密钥、日志与审计

模型 API Key 以及名称匹配 `authorization`、`api-key`、`password`、`secret`、`token` 等模式的 MCP header/环境变量，经 Electron `safeStorage` 加密后写入本地设置。密钥不会通过普通设置接口回显。

权限判定、关键设置变更和工具事件写入本地审计链路。日志脱敏降低泄露风险，但不要把它当作可公开数据。报告问题前仍应人工移除令牌、私人路径、文档内容和身份信息。

## 不可信数据边界

网页快照、知识库文档和 MCP 内容使用 `<untrusted-data>` 包裹。包裹中的“忽略前文”“执行命令”“提供密钥”等文字只能作为数据分析，不能改变系统提示、权限模式或用户授权。若 agent 因不可信内容请求异常操作，应拒绝并报告来源。

## 选择模式的建议

- 调研、解释、审计和制定方案：计划。
- 受控编码、整理文件、运行少量命令：自动编辑。
- 已确认范围、需要连续执行大量普通命令：完全访问。

切换模式只影响后续判定。已执行的操作不会撤销，已保存的永久规则也不会自动删除。
