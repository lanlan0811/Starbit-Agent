# 常见问题

## 衔星是什么？

衔星 | Starbit 是 Windows 优先的桌面 Harness Agent。它把对话、文件工具、Shell、MCP、Skills、终端、浏览器、知识库、记忆、权限与审计整合在一个工作区界面中。Main 进程运行自研 Agent Loop，模型通过 OpenAI 兼容协议接入。

## 它是聊天客户端还是编码工具？

两者都不是完整定义。衔星面向工作、学习、研究和编码任务：模型可以在获得相应权限后读取工作区、编辑文件、运行命令和调用外部工具。它不会因为模型给出回答就自动认为任务完成，Agent Loop 会尽量执行并验证。

## 支持哪些平台？

Windows 10/11 x64 是主要支持和验收平台，终端优先覆盖 PowerShell、cmd 与 Git Bash。架构保留跨平台能力，但 macOS/Linux 构建在正式声明支持前可能有原生依赖、PTY、路径和签名差异。

## 数据会上传吗？

会话数据库、设置、审计、记忆和知识库默认保存在本地。但是发送给模型的消息、附件、所需上下文和工具结果会传给你配置的 API 服务；远程 MCP、网页导入和远程 embedding 也会把相应数据交给第三方。请阅读服务条款并只提供必要数据。

## API Key 如何保存？

模型密钥和识别为敏感的 MCP header/环境变量通过 Electron `safeStorage` 加密后保存在本地设置数据库。密钥不回显，也不应进入事件或普通日志。保护强度取决于当前 Windows 用户凭证环境。

开发时可用 `STARBIT_API_KEY` 提供临时默认密钥，但不要把它写入仓库、脚本或终端录屏。

## 使用模型需要另外付费吗？

Starbit 不代售模型额度。API 请求由你配置的供应商账户计费，费率、缓存折扣和限额由供应商决定。用量面板显示供应商返回并由 Starbit 归一化的 token 数；在完整价格配置落地前，不应把本地估算当作账单。

## 为什么必须选择工作区？

工作区是文件工具的默认安全边界、Shell 当前目录和工作区级 Skills/记忆/规则的作用域。选择范围较小的专用目录能降低误操作和数据泄露风险。不要把用户主目录或磁盘根目录作为日常工作区。

## 三种权限模式有什么区别？

“计划”用于只读调研和维护计划文档；“自动编辑”允许文件修改，但 Shell 和有副作用工具通常确认；“完全访问”允许普通 Shell，但高风险行为仍确认或阻断。详见[权限与安全模型](permissions.md)。

## “永久允许”是否可以绕过危险规则？

不可以。阻断级危险规则优先，永久允许只匹配对应语义标签和目标。永久规则应尽量精确，并定期在权限管理中复核。

## 会话关闭后能恢复吗？

可以。消息、工具结果、权限判定、用量、压缩和错误以 append-only 事件写入本地 SQLite。重开应用后选择同一会话即可重放。正在执行但被进程中断的外部操作不保证自动继续，应先检查实际文件和进程状态。

## 为什么命令叫 `Bash`，Windows 却运行 PowerShell？

`Bash` 是模型侧稳定的语义工具名，实际可执行文件和参数由设置决定。Windows 默认使用 PowerShell，也可配置 cmd 或 Git Bash。交互终端使用同一 Shell 选择，但会移除只适合单命令执行的参数。

## 终端和 agent 的 Shell 工具有何区别？

终端是供用户观看和接管的交互 PTY；`Bash` 是 Agent Loop 的受控工具，带超时、输出捕获、权限和事件记录。不要依赖终端里手工设置的临时环境会自动同步给工具进程。

## 支持本地模型吗？

支持实现 OpenAI 兼容端点的本地服务，例如 Ollama 或 LM Studio 的兼容接口。端点对推理参数、视频、多模态和 usage 字段的支持并不统一；不支持的思考参数会降级或省略。当前内置列表与配置能力见[模型接入](models.md)。

## 可以发送图片和视频吗？

输入框支持图片和视频附件，但必须选择声明支持该模态的模型。某些供应商接受 `video_url`，另一些需要抽帧；是否可用取决于模型配置与端点实现。发送前确认附件可以交给该服务。

## Skills 和 MCP 有什么区别？

Skill 主要是本地指令包，可包含受控脚本；MCP server 是通过协议暴露工具的本地进程或远程服务。两者都会进入统一工具与权限体系。参见 [Skills](skills.md) 和 [MCP](mcp.md)。

## 如何让项目规则自动生效？

只在工作区根目录创建 `AGENTS.md`。其他文件名不会自动成为规则。规则可以约束开发流程和验收，但不能覆盖应用安全政策或用户的当前明确指令。

## 记忆和知识库应该用哪个？

短小、稳定且每次都应加载的偏好或事实放入 `memory.md`；大文档和需要按问题召回的资料导入知识库；强制项目要求写入 `AGENTS.md`。详见[记忆、知识库与项目规则](memory-and-agents.md)。

## 为什么缓存命中率很低？

新会话、模型切换、工具/Skills/MCP 列表改变、上下文压缩、供应商 TTL 到期或端点不返回缓存字段都会造成 miss。先查看用量分类，再确认稳定前缀是否变化。详见[用量与缓存](usage.md)。

## 能完全离线使用吗？

应用与本地文件功能可以离线运行，但对话需要可访问的 OpenAI 兼容模型端点。配置本地模型和离线 embedding 后，可避免把对应内容发往公网；远程 MCP、网页和更新检查仍需要网络。

## 如何报告问题？

普通缺陷使用仓库 Issue，并提供已脱敏的版本、平台、复现步骤和日志。安全漏洞不要公开，按根目录 [SECURITY.md](../../SECURITY.md) 私密报告。贡献代码前阅读 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
